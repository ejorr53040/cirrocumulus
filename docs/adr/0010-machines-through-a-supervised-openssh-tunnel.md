# Machines are reached through a supervised OpenSSH tunnel

A Machine is a computer the Node agent reaches over SSH so Apps can run on it without KVM or the agent. The agent runs the system's OpenSSH `ssh`, one long-lived process per Machine, rather than speaking SSH itself. Each runs with `-F` naming a root-only config file of its own, never root's own config, which holds every option: the Machine's host, port and user, `BatchMode`, the agent's own Ed25519 key (`IdentitiesOnly`), `StrictHostKeyChecking=yes` against a `known_hosts` file of the agent's that holds each Machine's pinned key under its name (`HostKeyAlias`), and the forwards. Its arguments, which every local user can read, are `-F <file> -N -- <Machine name>` and nothing more. `ServerAlive*` notices a dead link with no traffic. The agent learns the connection is up from `ssh`'s `Authenticated to` line at `LogLevel=VERBOSE` followed by every forward socket appearing (below), and why it went down from the last line on stderr that isn't VERBOSE's own chatter. An `ssh` dies with the agent (`PR_SET_PDEATHSIG`), so a crash never leaves a connection nothing owns. One that ends is run again after a wait that doubles from 1 second to 30, and starts over once it has logged in; one that ends on a failed host-key check is not, nor is it started again when the Machine's Apps change, so a Machine presenting another key stays down until it is removed and added again (or the agent restarts, which tries it once more). The retry wait is fixed in the agent rather than configurable: a Machine that comes back is found within the wait reached by then, and the tests allow for the 30-second cap. A host key is pinned only by fingerprint, given with `--host-key` or confirmed by the operator after a scan; the scan asks for the Ed25519 key alone, since each key type is a pre-auth connection that OpenSSH's `PerSourcePenalties` counts against the Node.

Each Machine-backed App is forwarded from a Unix socket, not a port on the Node's loopback: `LocalForward <dir>/<app>.sock localhost:<route port>`, where `<dir>` is a directory made for one `ssh` run under `state_dir/ssh`, mode 0700, and removed with the run. `ssh` creates the socket 0600 (its default `StreamLocalBindMask`), and the edge connects to it. `ssh` says nothing once its forwards are bound, so the Machine is marked up when it has logged in and every socket in the run's directory exists; the directory is new for each run, so a socket in it is that run's, with no stale one to unlink (`StreamLocalBindUnlink` isn't needed). (Amended 2026-11-17; the forwards were loopback TCP ports at first, see below.)

## Considered options

- **An SSH library in the agent (`russh`).** Finer control over channels, but a large new dependency in a root process, and its own host-key and crypto code to trust instead of OpenSSH's. Rejected.
- **Require Machines to be routable and dial them directly.** No tunnel at all, but no Machine behind NAT or a firewall, and plaintext from the Edge across whatever network lies between. Rejected.
- **The Machine dials the Node (a reverse tunnel).** Works behind NAT, but needs the Node to accept SSH from Machines and Machines to hold a credential for the Node. Left for later.
- **Trust on first use without confirming.** Simpler `machine add`, but the first connection's network decides what's trusted from then on. Rejected; the operator confirms or gives the fingerprint.
- **Forward from ports on the Node's 127.0.0.1.** What the first version did, with no `sockaddr_un` length limit, but the port namespace is every local user's. Between the agent choosing a free port and `ssh` binding it, any local user can take that port, or hold every free one (ordinary fd limits allow that), and with `ExitOnForwardFailure` each run then fails, keeping every App on the Machine down; any local user can also connect to a bound forward past the edge. Choosing fresh ports per run and keeping them out of `ssh`'s arguments narrowed the race but couldn't close it, and `ssh` can't take over a listening socket the agent bound first. Replaced by root-only Unix sockets.

## Consequences

Machines need OpenSSH (`ssh`, `ssh-keygen`, `ssh-keyscan`) on the Node, 6.7 or later for Unix-socket forwards; `cirro node install` warns when `ssh` is missing. Status comes from parsing `ssh`'s VERBOSE output, so a change to that line's wording would show every Machine as unreachable; the integration tests run against the real `sshd` and `ssh`. Every Machine shares the agent's key, so one key's compromise opens them all. A forward socket's path, `<state dir>/ssh/<n>/<app>.sock`, must fit in a `sockaddr_un` (107 bytes): with App names of at most 32 characters, a state dir of up to 50 characters always fits. Nothing on the Node but the agent reaches a Machine-backed App except through the edge.
